# Distributed AI Compute 2.0 (No Docker) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Install the VS Code extension and run any task in parallel on this computer, or spread it over many computers, with no Docker and nothing installed permanently on the worker laptops.

**Architecture:** The master stops being 6 Docker containers. It becomes 3 local processes started by the extension: `ssh-executor` and `storage-service` (Python, each with its own SQLite file) and the Go `extension-gateway`, which ships inside a platform-specific `.vsix`. `uv` provides Python 3.11 without a system install. A built-in "This computer" node runs tasks through a local transport (subprocess instead of SSH). Remote workers keep the existing SSH sandbox model. Training keeps one sandbox per worker for the whole run, so the shard is sent once. Docker mode stays available for shared, multi-user masters.

**Tech Stack:** Python 3.11, FastAPI, SQLAlchemy 2.0 async with `aiosqlite`, paramiko, Go 1.27, TypeScript (VS Code API ^1.90), `uv`, vitest, pytest.

**Spec:** The design agreed in the session of 2026-11-16 is summarised in the **Design** section below. There is no separate spec file.

## Design (what was decided)

| Decision | Choice | Why |
|---|---|---|
| Database | SQLite, one file per service (`executor.db`, `storage.db`) | The only Postgres-specific code is the `UUID` type; the two services never share tables (ssh-executor reads datasets over HTTP) |
| Processes | 3 (2 Python + Go), not 1 | Each service imports top-level modules named `config`, `models`, `database`, `routes`; merging them means renaming every module. Keep that out of 2.0 |
| Go gateway | Keep it and cross-compile it into platform-specific `.vsix` files | It has its own handlers, JWT and local-token code (~3,600 lines); porting gains nothing |
| Python | `uv` (pinned release, downloaded once) creates a venv with Python 3.11 | Works with no system Python, on all 3 OSes |
| Local parallel work | Built-in node `execution_backend = "local"` | The column already exists (default `'ssh'`); the tests already have a local transport |
| Training | Federated averaging through the master (unchanged); one sandbox per worker per run | Workers never connect to each other and open no ports; the shard is sent once instead of every round |
| Worker packages | Master downloads wheels once and uploads them into the sandbox | No internet needed on the worker, no download per laptop; the environment is still deleted with the sandbox |
| Dashboard | Docker mode only in 2.0 | It needs nginx and a Node build |
| Docker | Still supported (`platformMode: docker`) | Postgres for shared team masters; existing 1.x installs keep working |

## Global Constraints

- Worker laptops need only SSH and `python3`. Nothing outside the task sandbox may persist unless the worker's owner turns on "Set Environment Cache…" (`env_cache_gb > 0`).
- Every master port listens on `127.0.0.1` only: gateway `8090`, ssh-executor `8011`, storage `8001` (the same numbers as Docker mode).
- Secrets `JWT_SECRET` and `SSH_CRED_KEY` are generated once (48 random URL-safe bytes each) and kept in `<globalStorage>/master/secrets.env` with mode `0600`. **Losing `SSH_CRED_KEY` makes every stored worker credential unreadable**, so it is never regenerated once it exists.
- Supported `.vsix` targets: `darwin-arm64`, `darwin-x64`, `linux-x64`, `linux-arm64`, `win32-x64`, `win32-arm64`.
- VS Code engine stays `^1.90.0`. Python services stay on Python 3.11.
- Version: everything ships as `2.0.0` (`PLATFORM_RELEASE` equals the `package.json` version; a unit test already enforces this).
- Commits carry no AI co-author or contributor lines.

## Review Focus

1. **Port 8090 is already taken by a 1.x Docker master.** Expected: when `/health` answers, connect to it and do not spawn a second master (Task 8 test `connects to a running Docker master instead of starting local`).
2. **A 1.x user upgrades.** Their data is in the Postgres volume. Expected: `platformMode: auto` keeps Docker for anyone who already set up Docker (Task 6 test `auto keeps docker for an existing docker install`).
3. **VS Code crashes and leaves the master running.** Expected: the next start finds the stale pid file, stops that process tree, then starts cleanly (Task 4 test `test_stale_pidfile_is_cleared`).
4. **Windows user folder with spaces or non-ASCII characters** (`C:\Users\José Doe\AppData\...`). Expected: everything still starts. Paths are passed as argv arrays, never through a shell (Task 6 test `launch args keep paths with spaces as single arguments`).
5. **Two runs reserve the same worker cores at once on SQLite.** `with_for_update()` is ignored on SQLite. Expected: one reservation wins and the other is refused (Task 3 test `test_concurrent_reserve_on_sqlite`).
